## Evidencia de instalación automatizada

El workflow [.github/workflows/release-candidate.yml](../../.github/workflows/release-candidate.yml) parte de checkout limpio, copia la plantilla privada, construye PHP con MongoDB, inicia MongoDB y Redis, diagnostica ambos motores, instala esquemas, repite las dos cargas, comprueba el flujo PHP y reinicia la aplicación. La grabación y la comprobación de duración entre 180 y 300 segundos son opcionales y solo se ejecutan manualmente al activar `grabar_demo`. Por ahora quedan pendientes.

El artifact `seguimiento-4-instalacion-demo` conserva los diagnósticos. Al activar la grabación también conservará video, metadata y capturas. La prueba no utiliza Webmin ni reutiliza sus conexiones. Los resultados de CI deben enlazarse al run de la versión, sin atribuir la ejecución a otro integrante.

## Requisitos por motor

- Redis: [mapa de claves y TTL](../redis-claves.md), prefijo grupo3, string sorted set hash, invalidación y ausencia de vaciados globales.
- MongoDB: [script mongosh](../../scripts/seed-mongosh.js) idempotente, URI leída del entorno privado y datos sintéticos. Se conserva el generador PHP anterior.
- SQLite: no se utiliza, conforme al alcance acordado de MongoDB y Redis.

## Límites y cierre académico

La validación PHP protege escrituras hechas por OpenDesk. Activar validadores nativos en Webmin continúa dependiendo de permisos administrativos ya documentados en S3. Los avisos son internos y no se implementa correo SMTP.

El candidato puede usarse para revisar la entrega, pero no se marca la prueba humana como terminada sin una ejecución real de otra persona. Al completar ese registro, incorporar el video y confirmar la exposición, publicar v1.0.0 con la evidencia final. Si la exposición es en semana 16, el docente exige directamente v1.0.0.
